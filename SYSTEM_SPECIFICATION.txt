1. HIGH-LEVEL ARCHITECTURE & TRIGGER DESIGN
--------------------------------------------------------------------------------
The system is divided into THREE decoupled, asynchronous subsystems:
1. Daily Scraper Subsystem (`scraper.py` / `daily_scraper.yml`): Runs 1x/day.
2. Hourly Reels Publisher Subsystem (`publisher.py` / `hourly_publisher.yml`): Runs 20x-24x/day (Every 1h).
3. Satirical News Publisher Subsystem (`news/news_publisher.py` / `news_publisher.yml`): Runs 3x/day.

FEED & REELS TAB ISOLATION POLICY:
- Reels are published strictly to the Reels tab (`shouldShareToFeed: false`).
- The main profile grid is exclusively reserved for 4:5 vertical satirical news posts (`shouldShareToFeed: true`).

CRITICAL TRIGGER SPECIFICATION:
Native GitHub Actions `on.schedule` (cron) IS NOT USED due to unpredictable queue delays (30m to 11h),
dormancy bugs, and shared runner throttling.
All workflows use `on: workflow_dispatch` and are triggered externally via REST API calls from Cron-job.org:
- Daily Scraper Webhook (1x/day at 01:00 UTC):
  POST https://api.github.com/repos/rjydly/michael-ballson/actions/workflows/daily_scraper.yml/dispatches
- Hourly Publisher Webhook (20-24x/day, Every 1h):
  POST https://api.github.com/repos/rjydly/michael-ballson/actions/workflows/hourly_publisher.yml/dispatches
- Satirical News Publisher Webhook (3x/day at 11:00, 16:00, 21:00 Europe/Madrid):
  POST https://api.github.com/repos/rjydly/michael-ballson/actions/workflows/news_publisher.yml/dispatches
  Cron expression: `0 11,16,21 * * *` (Timezone: Europe/Madrid)
Headers required: Authorization: Bearer <GITHUB_PAT>, Accept: application/vnd.github+json, User-Agent: CronJobBot.
Body: {"ref": "main"}.

2. DAILY SCRAPER SUBSYSTEM (`scraper.py`)
--------------------------------------------------------------------------------
- Frequency: 1x per day.
- Target Volume: 20 posts published per day target.
- Account Targeting: Batches the top 8 Instagram profiles from `accounts.csv`.
- API Provider: Apify Actor `apify/instagram-api-scraper`.

COST OPTIMIZATION LAWS:
A) Batched Request: `directUrls` takes all 8 profile URLs in a SINGLE Actor call. 
   Limits the fixed "Actor Start" fee ($0.001) to exactly 1 per day ($0.03/month).
B) Omission of Date Filter: The input payload DOES NOT pass `onlyPostsNewerThan`. 
   Instead, `resultsLimit: 9` fetches the 9 latest posts per profile (72 posts total).
   Filtering by date (newer than 2 days) is executed locally in Python at $0.00 cost.
   Cost per post scraped = $0.0023. Total daily scraping cost = ~$0.16/day (~$4.90/month).

SCRAPING & QUEUE LOGIC:
1. Local Filtering: Post must be a Video, post ID must not exist in `processed_videos.json`,
   and timestamp must be >= `now() - 2 days` (parsed via ISO 8601 or UNIX timestamp).
2. Sorting: Candidates are sorted descending by `likesCount`.
3. Daily Queue Generation (TOP 20): Formatted into `today_queue.json` schema:
   `{"rank": idx, "id": "...", "username": "...", "likes": ..., "url": "...", "videoUrl": "..."}`.
4. Telegram Notification: Sends rich HTML-formatted summary message to Telegram (`TELEGRAM_TOKEN`, `CHAT_ID`).
5. Backup Persistence: Candidates 21+ with `likesCount > 1000` are synced to `backup_reels.csv` (`link,likes,status`).
6. Git State Persistence: `today_queue.json` and `backup_reels.csv` committed and pushed.

--------------------------------------------------------------------------------
3. HOURLY REELS PUBLISHER SUBSYSTEM (`publisher.py`)
--------------------------------------------------------------------------------
- Frequency: Every 1 hour (20x-24x per day).
- Primary Queue Strategy (`today_queue.json`): Pops candidate 0, processes video, updates state, publishes.
- Fallback Queue Strategy (`backup_reels.csv`): Reads highest likes candidate with `status == ""`.
- Circuit Breaker: Two pauses of 300s on consecutive failures; aborts after 2 pauses to protect DB.
- Grid Protection: Buffer metadata sets `metadata.instagram.shouldShareToFeed: false` so reels
  never contaminate the main news grid.

--------------------------------------------------------------------------------
4. SATIRICAL NEWS DATABASE & PUBLISHER SUBSYSTEM (`news/`)
--------------------------------------------------------------------------------
- Frequency: 3x per day (11:00, 16:00, 21:00 CET).
- Target Audience: Young adults, Millennials, and Gen Z in Europe and North America.
- Content Strategy: Deadpan journalistic satire on hyper-relatable everyday modern struggles
  (workplace burnout, dating, supermarkets, budget travel, streaming paralysis).
- Database File: `news/news_database.csv`
  Schema: `id,headline,search_query,caption,status`
  Quoting: `csv.QUOTE_ALL` (ensuring multi-line text integrity).

NEWS EXECUTION LIFECYCLE (`news/news_publisher.py`):
1. Reads `news/news_database.csv`, extracts first row where `status == ""` (empty).
2. If queue is empty, sends an alert to Telegram and terminates safely.
3. Fetches high-resolution stock photography via Pexels API using `search_query`.
4. Renders the 1080x1350 composite image via the Graphic Rendering Engine.
5. Saves image to `images/news_post.jpg`.
6. Mode Evaluation:
   - If `MODE_PROVA = True`: Sends preview to Telegram and stops without pushing or posting.
   - If `MODE_PROVA = False`:
     a. Marks news ID as `status = "done"` in `news/news_database.csv`.
     b. Stages, commits, and pushes `images/news_post.jpg` and `news/news_database.csv` to GitHub.
     c. Publishes image to Instagram Feed via Buffer API.
     d. Publishes image to Facebook Page via Buffer API.
     e. Dispatches notification to Telegram with the generated asset and caption.

BATCH GENERATION SUBSYSTEM (`news/generate_batch.py`):
- Engine: Google Gemini API (`gemini-3.6-flash`).
- Batches 15 items per prompt to prevent token clipping.
- Automatically appends structured rows to `news/news_database.csv` with retry logic (3 attempts, 10s backoff).

--------------------------------------------------------------------------------
5. GRAPHIC RENDERING ENGINE SPECIFICATIONS (Pillow)
--------------------------------------------------------------------------------
CANVAS GEOMETRY:
- Target Dimensions: 1080 x 1350 pixels (Aspect Ratio 4:5 Instagram Portrait).
- Scaling: Centers and crops input stock photography to fill the canvas without distortion.

DEEP ATMOSPHERIC BLACKFADE:
- Origin: Starts high up at `y = int(CANVAS_H * 0.28)` (28% from the top, ~378px).
- Curve: Exponential darkening `alpha = int(255 * (progress ** 1.15))` reaching pure black
  behind the text block for 100% legibility.

BRANDING & SEPARATOR LINE:
- Logo Asset: `assets/logo.png` (Fallback text: `@HOMER.NEWS` if file missing).
- Geometry: Fixed height `target_h = 110px`, max width cap 360px.
- Position: Centered horizontally at `y = separator_y - (target_h // 2)`.
- Divider Lines: Symmetrical 3px horizontal lines (`RGB(210, 210, 210, 220)`) with 30px padding from logo.

TYPOGRAPHY & DUAL-COLOR TOKENIZER:
- Font: *Anton Regular* (`assets/Anton-Regular.ttf`), size 76px.
  (Auto-downloads from Google Fonts repository if missing locally).
- Line Height: `font_size * 1.12` (~85px).
- Tokenizer: Parses markdown asterisks (`**keyword**`).
  - Standard words: Pure White (`RGB(255, 255, 255)`).
  - Highlighted words: High-Voltage Yellow (`RGB(255, 230, 0)`).
- Word Wrapping: Centered line-by-line rendering calculated via character bounding boxes.
- Footer Element: "READ THE CAPTION" in Anton 26px (`RGB(160, 160, 160)`) at `y = CANVAS_H - 55`.

--------------------------------------------------------------------------------
6. VIDEO MEDIA PROCESSING & NORMALIZATION (MoviePy & FFmpeg)
--------------------------------------------------------------------------------
STRICT 1080x1920 CANVAS NORMALIZATION (REEL ASPECT RATIO 9:16 WITH BLACK BACKGROUND):
- Geometry: 1080 x 1920 canvas.
- Scaling factor: `scale = min(1080 / w, 1920 / h)`.
- Letterboxing: Black background `ColorClip(size=(1080, 1920), color=(0,0,0))` with matching duration.
- Frame 0 Thumbnail: Injects 0.1s `assets/thumbnail.png` at video start for automated cover selection.
- Compression: `codec="libx264"`, `audio_codec="aac"`, `bitrate="3500k"`, `crf="24"`, `pix_fmt="yuv420p"`.
- Size Guard: Hard limit at 48 MB to prevent GitHub push rejection.
