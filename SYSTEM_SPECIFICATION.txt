1. HIGH-LEVEL ARCHITECTURE & TRIGGER DESIGN
--------------------------------------------------------------------------------
The system is divided into TWO decoupled, asynchronous subsystems:
1. Daily Scraper Subsystem (`scraper.py` / `daily_scraper.yml`): Runs 1x/day.
2. Hourly Publisher Subsystem (`publisher.py` / `hourly_publisher.yml`): Runs 12x/day (every 2h).

CRITICAL TRIGGER SPECIFICATION:
Native GitHub Actions `on.schedule` (cron) IS NOT USED. GitHub's native scheduler suffers 
from severe queue delays (30m to 11h), dormancy bugs on fresh pushes, and shared runner throttling.
Instead, BOTH workflows use `on: workflow_dispatch` and are triggered externally via 
REST API calls from Cron-job.org:
- Daily Scraper Webhook: POST https://api.github.com/repos/rjydly/michael-ballson/actions/workflows/daily_scraper.yml/dispatches
- Hourly Publisher Webhook: POST https://api.github.com/repos/rjydly/michael-ballson/actions/workflows/hourly_publisher.yml/dispatches
Headers required: Authorization: Bearer <GITHUB_PAT>, Accept: application/vnd.github+json, User-Agent: CronJobBot.
Body: {"ref": "main"}.

--------------------------------------------------------------------------------
2. DAILY SCRAPER SUBSYSTEM (`scraper.py`)
--------------------------------------------------------------------------------
- Frequency: 1x per day.
- Account Targeting: Batches the top 8 Instagram profiles from `accounts.csv`.
- API Provider: Apify Actor `apify/instagram-api-scraper`.

COST OPTIMIZATION LAWS:
A) Batched Request: `directUrls` takes all 8 profile URLs in a SINGLE Actor call. 
   This limits the fixed "Actor Start" fee ($0.001) to exactly 1 per day ($0.03/month).
B) Omission of Date Filter: The input payload DO NOT pass `onlyPostsNewerThan`. 
   Passing date filters to Apify triggers a $1.30 / 1,000 results Add-on surcharge.
   Instead, `resultsLimit: 9` fetches the 9 latest posts per profile (72 posts total).
   Filtering by date (newer than 2 days) is executed locally in Python at $0.00 cost.
   Cost per post scraped = $0.0023. Total daily scraping cost = ~$0.16/day (~$4.90/month).

SCRAPING & QUEUE LOGIC:
1. Local Filtering: Post must be a Video, post ID must not exist in `processed_videos.json`,
   and timestamp must be >= `now() - 2 days` (parsed via ISO 8601 or UNIX timestamp).
2. Sorting: Candidates are sorted descending by `likesCount`.
3. Daily Queue Generation: Top 12 candidates are written to `today_queue.json`.
4. Backup Persistence: Candidates 13+ with `likesCount > 1000` are synced to `backup_reels.csv`.
   `backup_reels.csv` is maintained in strict descending order of `likesCount`.
5. Git State Persistence: `today_queue.json` and `backup_reels.csv` are committed and pushed.

--------------------------------------------------------------------------------
3. HOURLY PUBLISHER SUBSYSTEM (`publisher.py`)
--------------------------------------------------------------------------------
- Frequency: 12x per day (every 2 hours).
- Primary Queue Strategy (`today_queue.json`):
  1. Reads `today_queue.json`. Pops candidate 0.
  2. Downloads video. Primary attempt uses direct CDN `videoUrl` with custom Chrome `User-Agent`
     and 3 retries. Fallback attempt uses `yt-dlp` on candidate permanent URL (`https://instagram.com/p/...`).
  3. On success: Processes video, records post ID in `processed_videos.json`, saves `today_queue.json`,
     pushes state to GitHub, publishes to Buffer.
  4. If `today_queue.json` candidate fails completely: pops it and tries candidate 1.

- Fallback Queue Strategy (`backup_reels.csv`):
  If `today_queue.json` is empty or all candidates fail, execution falls back to `process_from_backup()`.
  Reads `backup_reels.csv`, filters for `status == ""` (empty string), selects highest likes candidate,
  downloads via `yt-dlp`, processes, marks `status = "done"`, and publishes.

CIRCUIT BREAKER PATTERN (CRITICAL ANTI-CASCADE PROTECTION):
`yt-dlp` or network blocks can cause continuous download errors. Without a circuit breaker,
a temporary block would iterate over all backup items and mark the entire CSV as `status = "failed"`.
Circuit Breaker Logic in `process_from_backup()`:
- Variable `consecutive_failures` tracks consecutive errors.
- If `consecutive_failures == 2`:
  - Triggers Pause 1: Sleep 300 seconds (5 minutes). Resets `consecutive_failures = 0`.
- If 2 consecutive errors happen again after Pause 1:
  - Triggers Pause 2: Sleep 300 seconds (5 minutes). Resets `consecutive_failures = 0`.
- If errors persist after Pause 2:
  - ABORTS execution immediately (`return False`).
  - Leaves all remaining pending CSV rows untouched (`status == ""`) to preserve the database.

4. VIDEO MEDIA PROCESSING & NORMALIZATION (MoviePy & FFmpeg)
--------------------------------------------------------------------------------
1080x1920 CANVAS NORMALIZATION (STRICT REEL ASPECT RATIO 9:16):
Instagram Reels require vertical 9:16 geometry. Input videos can be 1:1, 16:9, or arbitrary sizes.
Function `fit_clip_to_1080x1920(clip)` enforces a strict 1080x1920 canvas:
1. Calculates aspect ratio scaling factor: `scale = min(1080 / w, 1920 / h)`.
2. Resizes clip to `(new_w, new_h)` ensuring even integer dimensions.
3. Generates a black background `ColorClip(size=(1080, 1920), color=(0,0,0))` with matching duration.
4. Centers resized clip onto black background using `CompositeVideoClip([bg, positioned_clip])`.
5. Letterboxing (black bars top/bottom or left/right) is applied automatically for non-9:16 media.

FRAME 0 COVER IMAGE (THUMBNAIL) INJECTION:
Instagram Reel cover selection via Buffer API relies on selecting frame 0 (`thumbnailOffset: 0`).
1. Reads `assets/thumbnail.png`.
2. Converts image to 0.1s `ImageClip`, normalized onto the 1080x1920 black canvas.
3. Prepends thumbnail clip to main video using `concatenate_videoclips([thumb_clip, main_video])`.

EXPORT COMPRESSION & FILE SIZE SAFETY LAWS:
- Export Parameters: `codec="libx264"`, `audio_codec="aac"`, `ffmpeg_params=["-pix_fmt", "yuv420p", "-crf", "24"]`.
- Bitrate Cap: `bitrate="3500k"` (3.5 Mbps). Guarantees 1080p mobile quality while keeping size ~15-25 MB.
- GitHub File Size Safety Guard: Evaluates `os.path.getsize(output_path) / (1024 * 1024)`.
  If file size > 48 MB, raises Exception to prevent Git push rejection (GitHub 50MB warning / 100MB hard limit).

5. EPHEMERAL HOSTING & BUFFER PUBLISHING API
--------------------------------------------------------------------------------
EPHEMERAL HOSTING ARCHITECTURE:
Buffer API requires an internet-accessible HTTP/HTTPS MP4 URL to ingest video assets.
1. `videos/` directory is cleared at start of publisher run.
2. Output written to `videos/out.mp4`.
3. Executed `git add -f videos/out.mp4` (`-f` flag forces staging past any `.gitignore` patterns).
4. Executed `git commit` and `git push`.
5. `time.sleep(5)` delay enforces GitHub CDN propagation.
6. Direct URL constructed: `https://raw.githubusercontent.com/{repo}/main/videos/out.mp4`.

BUFFER GRAPHQL API PAYLOAD SPECIFICATION:
- Endpoint: `https://api.buffer.com`
- Mutation: `createPost(input: $input)`
- Payload Structure:
  {
    "input": {
      "text": DEFAULT_CAPTION,
      "channelId": BUFFER_CHANNEL_ID,
      "schedulingType": "automatic",
      "mode": "shareNow",
      "assets": [{
        "video": {
          "url": raw_url,
          "metadata": { "thumbnailOffset": 0 }
        }
      }],
      "metadata": {
        "instagram": {
          "type": "reel",
          "shouldShareToFeed": true
        }
      }
    }
  }
Note: `mode: "shareNow"` bypasses Buffer queues and posts instantly to Instagram.
Note: `metadata.instagram.type: "reel"` is MANDATORY; missing it causes Buffer API error:
"Invalid post: Instagram posts require a type (post, story, or reel)".

6. DATA PERSISTENCE & CSV SPECIFICATION
--------------------------------------------------------------------------------
`backup_reels.csv` Schema:
- Columns: `link,likes,status`
- `status` values:
  - `""` (Empty string): Pending backup item.
  - `"done"`: Successfully processed and posted.
  - `"failed"`: Download or processing failed permanently.
- Ordering Rule: CSV rows MUST ALWAYS be saved sorted descending by `likes` integer.

`processed_videos.json` Schema:
- JSON Array of strings (Instagram Post IDs).
- Maintained at max 500 items via slice `processed_ids[-500:]`.
